BPMN-Pilot guide

BPMN-Pilot is a free BPMN 2.0 editor that runs in your browser, with no account and nothing to install. Describe a process, or attach a procedure, a spreadsheet or emails: the AI co-pilot draws it in seconds, and you review it. You can draw by hand at any time.

BPMN-Pilot is a free BPMN 2.0 editor, installed on your machine or network. Connected through MCP to your AI agent and what it knows (mail, wiki, document base), it draws and checks the processes the agent describes, and you review them. The built-in co-pilot and drawing by hand work too.

Draw, style, check, present and share. No knowledge of BPMN is needed to start.

Getting started

A new diagram already holds a start, a task and an end. Build on them, or delete them.

  1. Pick a shape in the palette, on the left, and click the canvas to place it.
  2. Click the shape: its context menu adds the next element, already connected.
  3. Double-click to type the label.
  4. Name the file in the toolbar field. Exports use this name.

Every change is kept in the browser, and reopening the page brings your work back. FR or EN switches the language, Theme cycles through automatic, light and dark. The help follows these choices.

BPMN 2.0 is an Object Management Group standard, adopted by ISO as ISO/IEC 19510:2013. A .bpmn file made here opens in any compliant editor or engine.

Why BPMN rather than a flowchart?

In draw.io, Lucidchart or Visio, a shape means whatever its author meant. In BPMN, every symbol has a defined meaning: pools and lanes for who does what, events for what triggers or waits, gateways for how paths split and join. The file describes the process itself, not a picture of it: it can be checked, simulated, read by an AI agent and run by a workflow engine. It will still open in ten years, in another tool.

No account. Your diagrams stay in your browser. If you use the co-pilot, only the AI provider receives them. The site measures its traffic without cookies (see Privacy).

Drawing

The palette

At the top, the hand , lasso , space and connect tools. Below, the shapes: events, tasks, gateways, sub-processes, data, pools and lanes. , at the bottom, opens the full list of elements, with a search.

Choose the elements offered (palette profiles)

Palette, at the very bottom of the palette, chooses what the palette, the context menu and the Append element and Change element lists offer:

  • Full: every BPMN element, the starting setting.
  • Essential: start event, task, exclusive gateway, end event. Enough for a first diagram without the rest of the BPMN vocabulary.
  • Camunda 8: hides what the Camunda 8 engine does not run (complex gateway, transaction, cancel events), following the compatibility rules of Camunda Modeler. Useful before the Camunda export.

An orange dot on the button flags a narrowed palette. The profile does not change the diagram: an element already drawn stays as it is, and the AI co-pilot keeps all its tools. The choice is kept in this browser.

The context menu

It appears next to the selected element. For a task:

  • append an end, a gateway, a task or an intermediate event on the right, already connected.
  • Add text annotation places a connected comment.
  • Append element opens the list of everything that can follow.
  • Connect to other element, then a click on the target, draws a flow.
  • Change element changes the type without redrawing.
  • Delete removes the element and its flows.
  • Set color and Text formatting: see Colors and text.
  • Copy style remembers fill, stroke, font and text color. Paste style applies them to the selection.

Change element

The wrench, or the R key, lists the compatible types: a task becomes a user task, a service task, a call activity, a sub-process. Type a few letters to filter. The icons at the top right add or remove a marker: parallel multi-instance , sequential , loop .

Undo and redo

Undo and Redo, at the top left of the canvas, step through your actions and the co-pilot's one at a time. After Tidy up or a co-pilot layout, Undo returns to the previous state in one step, and older actions can no longer be undone. Opening a file starts a fresh history.

Search and zoom

Search, or Ctrl+F, looks through labels, IDs and documentation. Enter selects the element found and centers the view. Next to it, Zoom out and Zoom in change the zoom by one step, the percentage between them opens a slider to set the zoom from 20% to 400%, with a 100% button, and Fit shows the whole diagram.

Map, next to Search, unfolds the tree of the diagram: each process or participant, its subprocesses, the activities linked to a sub-level and the tasks linked to a decision table, on every level. A click opens the item, like its button on the canvas, and the level shown is marked. The same button is in the Presentation mode bar.

The tree has no names of its own: each line shows the name typed on the block, by double-click or in the properties panel. To rename a line, rename the block.

  • Process or participant: the participant's Name field, else Process name (process panel, with nothing selected). Without a name: "Main process".
  • Subprocess: its Name field. Without a name: "Subprocess".
  • Activity linked to a sub-level: its Name field, then, after an arrow, the Linked diagram of the Sub-level group, that is the file's name in My diagrams, when the two differ.
  • Task linked to a decision table: its Name field, else the identifier of the Linked decision (Decision table (DMN) group).

Each palette symbol has a meaning set by the standard. This memo groups them by family, then crosses events with what triggers them. The icons are the editor's own.

Task types

A small icon at the top left of the task says who or what performs it:

  • User: a person, in an application
  • Manual: a person, without an application
  • Service: a system, through an automated call
  • Script: a script run by the engine
  • Business rule: a decision, often a DMN table
  • Send: sends a message, then goes on
  • Receive: waits for a message

Markers

A marker at the bottom center of an activity says how it runs:

  • Loop: repeats while a condition requires it
  • Parallel multi-instance: one run per item of a list, at the same time
  • Sequential multi-instance: one run per item, one after the other
  • Compensation: undoes the work of an activity already completed
  • Ad hoc: activities in a free order

Event matrix

A single circle for a start, a double one for an intermediate event, a thick one for an end. A filled symbol throws, a hollow one catches. A dashed border marks a non-interrupting event: the activity or the process goes on. Colors and text

The brush and the A button of the context menu set the look.

  • One element selected: a small menu of five colors, then those Used in this diagram. More… opens the Style group of the Process panel.
  • Several elements: 17 ready-made colors and a Custom color…, or for the text: bold, italic, underline, size, font and color.

The Style group has three parts:

  • Shape: pale fills, bright fills (white text), then separate Fill and Stroke, with their hex code.
  • Text: bold, italic, underline, size, font and color. Auto picks black or white for the fill, Default text clears everything.
  • Copy and paste: Copy style and Paste style, then the last eight styles of the diagram, one click away.

Colors and styles are written to the .bpmn file following the standard, and Ctrl+Z undoes them. The PDF export drops underlining and swaps fonts for Helvetica or Times.

Check and tidy up

BPMN checks (bpmnlint)

bpmnlint checks the diagram as you draw. A red badge marks an error, an orange one a warning. Hover it to read the message and the rule name, which links to its explanation. The counter, at the bottom of the canvas, totals the whole diagram, collapsed subprocesses included, and says when findings are on another level ("level “Site rollout”"). A click goes to the next finding, errors first: it opens the right level, selects the element and shows its messages. The eye next to it hides or shows the badges.

Multi-level map (call activity)

Keep an overview of a few steps, and detail each one in its own diagram.

  1. Turn the task into a Call activity with Change element.
  2. In the Sub-level group, + Create the diagram of this level creates and links a diagram named after the activity. You can also pick one already saved.
  3. The Open badge, under the activity, goes down one level. The breadcrumb at the top of the canvas and ↑ Up take you back.

Each level change saves the open diagram to My diagrams. An unlinked activity shows a dashed + Link badge, a broken link a red one. The file keeps the linked diagram's name and the standard calledElement attribute. You can still move between levels in Presentation mode.

To share a map, export each level to .bpmn, under its diagram's name.
A level created from a server diagram goes to the server: the whole map opens from any browser.

Open, import, export (XML, SVG, PNG, PDF)

Open

Open reads a .bpmn, .xml or encrypted file, a table of steps, a workshop grid or a Mermaid flowchart. A file dropped on the page opens too. Paste XML…, in the same menu, takes BPMN XML copied from another tool or from an AI answer. Files from Camunda, Bizagi or Signavio are read, and their layout is computed if they lack one. The other way round, what is specific to BPMN-Pilot (probabilities, sub-levels, AI agent steps…) is ignored without error by other tools, and kept when they save the file again.

Create from a table (no AI)

From a table… turns a list of steps into a diagram. Paste the rows copied from Excel, header included, or pick a .csv, .tsv or .xlsx file. Nothing leaves the page. A preview counts steps, links, decisions and lanes, and flags errors before creating anything.

Documentation page (HTML)

Documentation page (HTML) produces a single .html file, readable without BPMN-Pilot and offline: attach it to an email or put it on an intranet. A click on an element of the diagram opens its sheet. All the sheets follow, in flow order. The page loads nothing from outside and prints with its sheets.

Exports asked of the AI

"Export the diagram to PDF": the co-pilot or an MCP agent produces the same file as the menu. The same goes for the documents of the menu: process report, procedure sheets, documentation page, RACI matrix, user stories, decisions (.dmn) and BPMN for Camunda 8 or 7, even when the matching module is off. Only the encrypted file stays a manual step, so the password never goes through the AI. It only downloads after a click on Download, in the banner at the bottom of the canvas.

The file also lands in the server's exports folder, without overwriting an existing file.

Encrypted file (AES-256)

Encrypted .bpmn file… asks for a password of at least 8 characters and downloads a .bpmn.enc file encrypted in the browser (AES-256-GCM, PBKDF2-SHA-256 key, 600,000 iterations). The password is stored nowhere: lose it, and the file is lost. Send it through another channel. Only BPMN-Pilot reopens this file, and it does not keep it in autosave.

Print

Print… prints the diagram alone on one page, landscape or portrait depending on its shape. For a very long process, prefer PDF or SVG.

Process panel

The right-hand panel shows the properties of the selected element, or of the process when nothing is selected. The button, right before AI co-pilot in the toolbar, hides it. Drag its left edge to widen it, double-click to restore the default width.

Responsibilities, systems and conditions (RACI)

The lane says which department acts. For each activity, set Assigned to (the R), the Systems used, and in the Responsibilities (RACI) group the Accountable (A), Consulted (C) and Informed (I). These fields feed the procedure sheets, the process report and the RACI matrix (Excel) export.

On a flow leaving an exclusive or inclusive gateway, Condition takes the rule in plain words ("Amount < 3000"). It is written to the standard conditionExpression element, and the Camunda export translates it for the engine.

Model an AI agent (ad-hoc sub-process)

BPMN 2.0 already has a shape for a step handed to an AI agent: the ad-hoc sub-process, whose activities are not connected. Whoever runs it picks which ones to start. For an agent, these are its tools.

  1. Select a task. In the AI agent group, check AI agent step: it becomes an ad-hoc sub-process marked AI agent.
  2. Place one task per tool inside it, with no flows, start or end.
  3. Describe in the documentation what the agent decides alone and what it must not do.
  4. Complete the pattern adds what is missing: a human review right after the step, and a boundary timer leading to manual handling.

The checks flag a step without human review or without a fallback (rules bpmnpilot/agent-review and bpmnpilot/agent-escalation). The marking lives in the bpmnpilot:agent attribute: other tools see an ordinary ad-hoc sub-process.

Review, checks and traceability

Around each answer, the co-pilot shows what it understood, what the editor checked and where the result comes from.

  • Request review. Before drawing a long description or a file, the model lists what is unclear or missing (actors, trigger, exceptions, delays), with a severity and the question to settle. It draws right away, listing its assumptions. Answer in your next message to refine.
  • Check report. After each change, the editor checks the diagram itself, with no AI, through six checks (table below).
  • Self-correction. If a check fails, the model fixes it, two rounds at most. A fix that improves nothing is dropped.
  • Traceability. Provider, model, duration, time and attached files are noted under each answer. Retry from the same source replays the request, for instance with another model.
  • Destination. A line above the input says where the message goes.

Review and self-correction cost extra requests. Review the request and correct automatically, in Options, turns them off.

Expert mode

Test a model and prepare it for execution: simulation, heatmap, report, event log, AI potential, compliance, Camunda, DMN, forms. None of this is needed to draw.

Turn on Expert mode

The small switch right of the Expert button, in the toolbar, turns the mode on or off in one click: the button turns blue, the expert sections show in the Process panel, and the browser remembers it. Expert opens the menu of the modules turned on, and picking one of its commands also turns the mode on. Commands that go through the co-pilot stay greyed out until a model is set.

Choose modules

Choose modules…, at the bottom of the menu, turns each feature on or off. The menu and the Process panel only show the modules turned on. By default, everything is on except the Camunda export, decision tables and task forms. The heatmap needs the simulation.

Turning a module off removes nothing from the file: values already entered stay. The co-pilot and MCP agents keep all their tools.

Simulation and heatmap

Simulation puts a play button on each start event. Click it: a token follows the flows, and you pick the path at exclusive gateways, or the autopilot picks it for you. The slider at the bottom of the canvas sets the speed, the log lists the steps. The canvas is locked during the simulation: Stop simulation gives it back. Until then, the co-pilot commands of the Expert menu stay greyed out, since they write into the diagram.

Branch probabilities

On a flow leaving a gateway, the Probability (%) field of the Token simulation group sets its share. Flows without a value split the rest. At an inclusive gateway, each flow is drawn by its own probability.

Propose probabilities asks the co-pilot for them, based on labels and documentation. Its values carry "Proposed by the AI co-pilot, to review" until you change them or check Keep the co-pilot's value. The value is written to the bpmnpilot:probability attribute.

Gateway autopilot

Autopilot, in the speed frame, lets each gateway pick its branch by itself when a token arrives, with the same rules as Run N tokens: from the flow probabilities, or from the decision table just before. An inclusive gateway takes each branch by its probability, at least one. Send several tokens in a row: the animation then shows the actual distribution, which you can follow on the heatmap. A click on a gateway's button still changes the branch, until the next token. The autopilot is off by default, and the choice is kept in this browser.

Process goals

In the same group, a goal sits on what it measures: the share of instances ending at an end event (at least 80% approved), or the number of passes per 100 instances on an activity (at most 15 document requests). After a token run, the report says whether it is met.

Heatmap

The heatmap colors each element and flow by the number of tokens that went through, from pale blue to red. It shows paths never taken, steps nearly everything goes through, and rework loops.

  1. Start the simulation and turn on Heatmap, in the speed frame.
  2. Coverage: send a few tokens down different paths. What stays dashed grey is never reached.
  3. Distribution: set the probabilities, enter a number of tokens (up to 10,000) and click Run. The result is instant.
  4. Read the badges: "31 · 31%" gives passes and share of instances, "131 · 1.3×" flags a loop.
  5. Deadlocks: a red "47 blocked" badge on a merge counts the instances that could never complete. A token waits there for a branch that was not taken, for example a parallel merge placed after an exclusive split. The legend gives the total, and the report turns it into an error finding with its improvement area.

After a business rule task linked to a decision table, a gateway without probabilities splits tokens by the table's rules. The heatmap counts passes, not durations or costs. The PDF report includes it as long as the diagram does not change.

Process report

The report turns the diagram into a document readable without a BPMN tool, and into a modeling review. In the Expert menu, under the Process report heading, PDF, Markdown or Word. It contains:

  • key figures and the diagram, with each element at issue circled;
  • findings: Error in red, Warning in orange, To complete in yellow, with their source;
  • improvement areas by priority, and goals met or not;
  • after a simulation, the heatmap and its figures, and the instances blocked on a merge;
  • the six checks, the decision tables, activities by lane and the full sequence.

It flags what is missing: gateways without a question, flows without an answer, activities without documentation. It grows with what you fill in, such as the process identity, RACI, AI potential and risks. The Word document can be restyled in your organization's colors.

Co-pilot analysis asks it for a reading of the process: it runs 100 tokens, reads the report and saves a summary (bottlenecks, rare paths, risks, ideas), linked to the elements. The analysis is kept in the .bpmn file, and the report shows it signed with the model and date, for review. It warns you if the diagram changed since.

Analyze an event log (process mining)

Your software (ERP, CRM, ticketing tool) records what really happened: for each case, which step and when. Analyze an event log (process mining) compares this log with the diagram.

  1. Pick a CSV (one row per step done) or an XES file, compressed or not. Try with the example loads 412 fictitious orders.
  2. Check the guessed columns: case, step and date are required, end and resource optional.
  3. Check how each step of the log maps to an element of the diagram.
  4. Analyze.

The panel that opens has three tabs:

  • Passes: the heatmap with real figures. Apply the log percentages to the gateways writes the observed shares into the probabilities.
  • Durations: the median wait before each step. The three longest are marked as bottlenecks.
  • Deviations: the share of conforming cases, the fitness (from 0 to 1), and deviations from most to least frequent. A click selects the element.

Without a diagram, Draw the process from the log… derives a first version, with no AI and exclusive gateways only. Ask the AI co-pilot sends it the totals for a finer model.

The log stays in the browser. Only totals leave it, and only if you check Keep the totals in the .bpmn file. Note that a CSV attached in the co-pilot chat goes to the AI provider in full.

Activities to hand to AI (AI potential)

This function helps decide where to bring AI into a process, and on what terms. It does not rate the co-pilot: it rates the activities of your diagram.

Which activities to hand to AI?, in the Expert menu, has the co-pilot go through each activity and class it:

  • Automatable: an AI agent or an automation can perform it, a person reviews the result.
  • AI-assisted: a person performs it, AI helps (prepare, summarize, check).
  • Human: it calls for judgment, a relationship or an accountability that stays with a person.

The co-pilot works from the activity's name, lane, documentation, assignee and systems. You get:

  • in each activity's Process panel, AI potential group: the Rating and the Why, and safeguard, that is the reason for the rating, and what to put in place to make it safe;
  • for each automatable or assisted activity, the risks of handing it to AI (error, personal data, no review…) and the matching controls, added to those already written in the Risks and compliance group;
  • in the chat, a three-line summary: where AI pays off first, and which risks to frame;
  • in the process report, a table that gathers it all.

It is a proposal to review: correct the rating in the panel when it does not fit your reality. You can also fill these fields by hand, without the co-pilot. The command needs a model set for the co-pilot and the AI potential module (Choose modules).

Risks, controls and requirements (compliance)

The report draws a risks and controls table, where a risky activity without a control turns yellow, and a compliance matrix by requirement. The procedure sheets include them.

Process identity

User stories and acceptance criteria

To move from the process to the tool that will serve it, an activity's User stories group takes its stories ("As a…, I want…, so that…") and acceptance criteria ("Given…, when…, then…"), one per line.

User stories by activity has the co-pilot write them, without touching those already written. It then lists the activities whose need is still unclear.

Decision tables (DMN)

A business rule task applies a decision: grant a loan, pick a price. The DMN standard, from the OMG like BPMN, describes it as a table: inputs, outputs, one rule per row. The editor links each task to its table, opens it in dmn-js and stores it in the .bpmn file.

Read a table: When… Then…

Each row is a rule. The When (and And) columns are the inputs, what the decision looks at. The Then columns are the outputs, what it decides. A rule applies when every input matches its cell. The Annotations column says why, with no effect on the result.

The Dish of the day example, taken from the official dmn-js examples, picks a dish from the season and the number of guests. With Winter and 12 guests, only rule 2 applies ("Winter", > 8): the dish is "Pasta".

Write a rule (FEEL)

The + under the table adds a rule. Each cell is written in FEEL, the DMN expression language. The column type (string, number, boolean, date…) is set with the pencil button of its header, with its name and allowed values.

CellExampleMatches
Text"Winter"exactly Winter. The double quotes are required: without them, Winter would be a variable name.
List"Winter","Spring"any of the values
Number12exactly 12
Comparison<= 8, > 1000a number or a date above or below a threshold
Range[10..30], ]1000..5000]between two bounds, included with [ ], excluded with ] [
Negationnot("Winter")anything but Winter
Any-any value, empty included

An output is written the same way: "Pasta", 10, true.

Hit policy

It says what to do when several rules apply. It is chosen above the table.

PolicyResult
Uniqueat most one rule may apply. Two rules together are an error in the table. The default.
Firstthe first rule that applies, from top to bottom. The order of the rows matters.
Prioritythe rule whose output comes first in the output's allowed values.
Anyseveral rules may apply if they give the same output.
Collectthe list of the outputs of every rule that applies, or their sum, minimum, maximum or count.
Rule orderthe list of the outputs, in row order.
Output orderthe list of the outputs, in the order of the allowed values.

An empty table

A table created from a task has a single Input column, a single Output column and no rule: the test bench cannot match anything. A box under the table recalls the steps and offers Fill in with the co-pilot, Open an example, which shows Dish of the day without touching your diagram (Close the example takes you back to your table), and the link to this help. It goes away with the first rule.

Link a task to its table

Each business rule task carries a badge: Table opens the linked table, a dashed + Table opens the Decision table (DMN) group, a red badge flags a missing decision. The group offers to create a table, link or import one, or have the co-pilot draft it. Once linked, it sums up the table and its findings.

The decision window

The table opens full screen, editable as in Camunda Modeler: rules, columns, types, allowed values, hit policy. The Requirements (DRD) tab shows the decision diagram. Decisions of the diagram…, in the Expert menu, opens that tab directly with every decision of the file. Cells are written in FEEL: "Pro", < 1000, [1000..5000], - for "any".

Back to the process or Esc stores the changes in the diagram, in one undoable step.

Test and compare a table

Test opens a test bench: enter one value per input, Evaluate highlights the matching rules and gives the result. One case per rule checks that each rule can fire. On a table with no rule, it says so instead of an empty result.

Compare lists what changed since opening, or against a .dmn file, rule by rule.

With no AI, the editor flags an empty table, unquoted text, an output outside its allowed values, overlapping rules under the Unique policy, an allowed value no rule covers, a task without a decision. Findings show in the group, in the report and in validate_diagram.

MCP agents in Expert mode

In the Docker version, and online with a local agent, an MCP agent also has these tools, whether Expert mode is on in the tab or not:

  • get_process_report: the report in Markdown, with or without 100 simulated tokens;
  • update_elements: documentation, assignee, systems, RACI, AI potential, risks, controls and requirements, user stories and acceptance criteria, probabilities, and the process identity on the diagram root;
  • export_diagram: besides the diagram, the report, the procedure sheets, the documentation page, the RACI matrix, the user stories, the decisions, the forms and the files for Camunda;
  • set_report_commentary: the process analysis;
  • get_decisions, set_decision_table, link_decision, test_decision: decision tables;
  • get_task_forms, set_task_form: task forms, the variables they fill in and the data check;
  • load_event_log, map_log_activities, apply_log_frequencies, check_conformance, get_log_summary: the event log, never returning a case or resource name.

Six MCP prompts cover these functions: propose_probabilities, rate_ai_potential and analyze_process send the same request as Propose probabilities, Which activities to hand to AI? and Co-pilot analysis; assess_compliance writes risks, controls and requirements; model_from_event_log draws the process from a log; fill_decision_table sends the same request as Fill in with the co-pilot, in the decision window.

Privacy

  • Your diagrams, settings and API keys stay in your browser. Neither we nor the host (GitHub Pages) can access them.
  • With the co-pilot, your messages, the diagram, your files and your key go straight to the chosen provider, under its own terms.
  • Dictation recognizes your voice on your device.
  • Your local AI agent (MCP), distinct from the co-pilot, if you turn it on, exchanges the diagram with the tab through a relay on your computer, with no other server. What it does with it depends on the agent and its provider.
  • GitHub Pages keeps technical logs, including your IP address.
  • The stable site measures its audience without cookies, following the recommendations of the CNIL (the French data protection authority, page in French) for audience measurement exempt from consent. The IP address only serves to locate the country, region and city, and is not recorded. Collected: the page viewed, the referrer, the device and a few actions without their content (create, open, export, use the co-pilot, provider type, active time in ranges, click on the support link). "Do Not Track" and "Global Privacy Control" turn the measurement off.
  • The site loads no third-party script.

    • Connect your AI agent (MCP)

    Your own AI agent, installed on your computer (Claude Desktop, Claude Code, Cursor, GitHub Copilot in VS Code…), reads and draws in the diagram open in this tab, with the same tools and prompts as in the Docker version. It goes through a small local relay, bpmn-pilot-mcp, that it starts itself: the diagram goes from the agent to the tab on your computer, through no other server, and the relay writes nothing to disk.

    Not to be confused with the AI co-pilot. The co-pilot is built into the page and calls the provider with the API key entered in Options. The MCP agent is your own assistant, with its own subscription, model and context (mail, documents, memory): no API key is entered in the page.

    1. Click MCP in the toolbar and pick your agent. For Claude Desktop, Download bpmn-pilot.mcpb, then double-click the file: Claude Desktop runs the relay itself, with no Node.js to install. For other agents, copy the line or block shown into their MCP settings (Node.js 20 or later).
    2. Turn on Local agent. Until then, the page opens no connection to your computer. Chrome and Edge ask once to allow access to the local network: accept.
    3. Ask your agent: "Describe the diagram open in BPMN Pilot." The button then reads "MCP:" followed by the agent's name.

    The agent works in the tab used last: keep it open while it draws. An export comes back to the agent, or waits in the page behind Download. Safari blocks the connection from an HTTPS page to the computer: use Chrome, Edge or Firefox. What goes where is detailed in Privacy.

    Without an open browser (headless mode)

    By default, the agent draws in an open editor tab. With docker-compose.headless.yml instead of docker-compose.image.yml (see the README), it works with no tab at all: a renderer service, a headless Chromium cut off from the internet and the API keys, opens the editor in an invisible tab, which closes after 5 minutes without a call. Each diagram drawn this way is saved on the server in My diagrams, under a name such as "Agent 2026-11-28 14h05".

    If you open the editor meanwhile, a banner says so. Open loads the diagram in your tab, and the agent carries on there. Without that click, it never touches the diagram in front of you. With the returnFile option, export_diagram returns the file to the agent.

    Your files in the Docker version

    The server stores everything in bpmn-data, next to its compose file (or in BPMN_DATA_DIR):

    • diagrams: one .bpmn per diagram of My diagrams. A .bpmn copied here appears in the list. Leave the hidden .index.json file in place.
    • exports: exports to the server. Nothing is overwritten: a second My process.pdf becomes My process (2).pdf.

    Install on your device (PWA)

    Once installed, BPMN-Pilot opens in its own window, from the Start menu, the Dock or the home screen.

    • Chrome and Edge: Install in the toolbar, when the browser offers it, or the icon in the address bar.
    • Safari on Mac: File, Add to Dock.
    • iPhone and iPad: Share, Add to Home Screen.
    • Firefox on desktop does not install PWAs.

    Offline (service worker)

    After a first visit, the editor and the help open without a network. The co-pilot needs one. When a new version comes out, a banner offers to Reload, keeping the current diagram.

    On iPhone and iPad, the installed app has its own storage, separate from Safari. Move a diagram from one to the other as a .bpmn file.

    The Docker version installs on localhost or over HTTPS. It does not work offline: the co-pilot, the MCP server and saved diagrams go through the server.

    On a phone or tablet

    The editor is made for a computer, a mouse and a keyboard. On a phone it is for viewing: open a file or a record, zoom with your fingers, export. Placing shapes, typing and using the panel are tedious there, and the last toolbar buttons fall off the screen. Below 900 pixels wide, a banner says so once.

    To model, use a screen at least 1280 pixels wide, or a tablet in landscape with keyboard and mouse.

    FAQ

    Do I need an account?

    No. Only the AI co-pilot needs an API key from a provider.

    No. Only the AI co-pilot needs an API key, on the server or in Options.

    Can I use the editor without AI?

    Yes: drawing, checks, simulation, saving and exports work without a key.

    My diagrams are gone. What happened?

    They live in a single browser, on a single device: absent elsewhere, in private browsing or after clearing the site data. Export to .bpmn what you want to keep.

    Those in This browser only show there, and not in private browsing or after clearing the site data. Those on the Server open everywhere.

    "Test" fails with OpenAI.

    OpenAI sometimes refuses calls made from a web page. Pick another provider, or the Docker version, which goes through its server.

    My MCP agent does not draw.

    Check in MCP that Local agent is on, and that the agent is running: it starts the relay. If the window keeps saying "Waiting for the relay", restart the agent. If it reports that port 3333 is already in use, another agent already runs the relay: close it. In Chrome or Edge, a refused local network access is restored from the padlock in the address bar.

    My MCP agent does not draw.

    The agent draws in the last editor tab used: keep it open, or switch to the headless mode. The badge should read "MCP: ready", then the agent's name once it connects ("MCP: Claude Code"). A click gives the address and settings again.

    A 401 "MCP is closed" error means the editor is served under a name other than localhost, without a token. Generate a token in Connect an agent, put it in MCP_TOKEN, restart, and paste the setting into the agent again.

    An export to the server, or a save to My diagrams, fails.

    The server cannot write to its data folder, which the message names. The data-init service prepares it at each start. If the error persists, the folder belongs to another user than the server's (1000, or PUID and PGID): see docker compose logs mcp.

    How do I check what my model can do?

    docker compose exec mcp node mcp/check-providers.js tries each model set on the server: answer, tool call, image, PDF. It tells a setup error from a model limit, for a few hundred tokens per model.

    The co-pilot drew something unexpected.

    Undo, on the pill, reverts the whole answer. Or ask for the fix in a few words. A precise description (actors, decisions, error cases) and a stronger model give better results.

    Can I open my files in another BPMN tool?

    Yes: Camunda Modeler, Bizagi, Signavio and any BPMN 2.0 compliant tool.
